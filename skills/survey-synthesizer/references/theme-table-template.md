# Theme-Table Template

The core output: one row per theme, with prevalence, representative quotes, and
dissent kept visible. This table is the spine of any report built from it.

## Table

```
# Open-Response Synthesis — <survey / source>
Responses: <n> · Substantive: <n> · Blank/n-a: <n> · Web/context: <as relevant>

| Theme | Prevalence | Representative voices | Dissent / minority view |
|---|---|---|---|
| <theme 1, named in respondents' terms> | ~<share> raised it; <intensity note> | "<verbatim quote>" · "<verbatim quote, chosen for range>" | <the counter-view, with its prevalence, or "none notable"> |
| <theme 2> | … | … | … |
```

## Filling the columns

- **Theme** — name it the way respondents would recognize, not in the survey's
  bureaucratic terms. "The workload spikes at midterm" beats "Temporal distribution
  concerns."
- **Prevalence** — a plain fraction or count plus an intensity note ("~a third; several
  strongly"). Avoid false-precision percentages on qualitative data.
- **Representative voices** — two or three verbatim quotes per theme, chosen for range
  (typical + edge), not just the sharpest line. Trim with […] and note it.
- **Dissent / minority view** — the strongest opposing or complicating voice, with its
  prevalence. "None notable" is a valid, informative entry.

## Ordering

Lead with the highest-prevalence or highest-stakes themes, but don't bury a small-but-
critical theme (a safety issue, an equity concern) just because few raised it — flag
those explicitly near the top even at low prevalence.

## Accompanying the table

Pair the table with the quality read (sample, self-selection, non-response, limits)
so no one mistakes the themes for population-level measurement. The table shows what
was said; the quality read says how far it can be trusted.
